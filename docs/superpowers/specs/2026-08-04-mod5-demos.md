# Module 5 demos — design spec (2026-08-04)

Four demos for Control module 5 ("High-stakes control"). All content
restates the module's human-authored sources (the lesson stub's prose, the
embedded readings' own claims, and the Ctrl-Z paper). No new curriculum
claims. House idiom throughout: hand-rolled inline SVG, Tailwind theme
tokens, `SlideStepper` for stepper demos (one scene, layers fade by step).

## 1. `high-stakes-graph` — interactive control graph (lesson c-mod5-l1)

Replaces the static `/images/high-stakes-control-graph.svg` in the lesson.
SlideStepper, 5 steps, one SVG scene reproducing the static graph's
geometry (four 180°-rotationally-symmetric regions):

1. **The axes** — incrimination per action (y) vs. number of actions needed
   to cause a catastrophe (x); all regions faint.
2. **High-stakes** — the left half of the diagonal band lights up (few
   actions needed). Caption = the lesson's definition sentence.
3. **Low-stakes** — the right half of the band (lots of actions needed).
4. **The corners** — top-right "trivially solved with random auditing",
   bottom-left "probably hopeless?" (the graph's own labels).
5. **Why the diagonal?** — the lesson's inverse-correlation paragraph:
   fewer actions ⇒ each action bigger ⇒ more incriminating.

## 2. `live-failure-plane` — latency × damage (synchronous-monitors reading)

Non-stepper. A 2D plane: x = attack latency (long grace period → none),
y = rate of damage (low → high). The live-failure region (short latency,
high damage) is shaded amber. The post's own examples are clickable points;
selecting one shows the post's description in a caption panel:
code backdooring, API-key compromise, access-credential compromise,
weight exfiltration, rogue internal deployment (with the post's
uncertainty noted). Spliced after block b-0009, where the post
characterizes live failures.

## 3. `agent-architecture-threats` — threat-scenario stepper (systems-architecture reading)

SlideStepper, 7 steps, one scene: User, Scaffold server, Inference server
(holds weights), Execution server (sandbox), Internet. Steps: (1) the basic
architecture and loop; (2) the safety insertion point in the scaffold
(monitor / audit / defer before executing); (3) weight exfiltration from
the execution server to the internet; (4) hacking the inference server from
the execution server; (5) compromising servers via committed code (the
post's "best self-exfiltration strategy" note); (6) the rogue agent loop on
the execution machine's own GPUs; (7) the rogue scaffold that calls the
inference API (and why basic API monitoring catches it). Attack paths draw
in red; each caption restates the post's section. Spliced at the end of the
"Different ways the AI could compromise this" section.

## 4. `defer-to-resample` — resampling mechanics (Ctrl-Z paper)

Interactive, schematic (labelled as such — these are illustrative normal
distributions, NOT the paper's empirical data; the qualitative behavior
restates §3.2 and Figure 4-right). Sliders: number of samples per step
k (1–6) and the red team's attack continuation probability c (20–100%).

Model: suspiciousness s; innocent ~ N(0,1), attack ~ N(2,1). An attacked
step draws one attack sample plus k−1 resamples, each an attack with
probability c else benign (the mixture F_M = c·F_A + (1−c)·F_I). The panel
draws the min-of-samples densities for an innocent step and an attacked
step. Defer threshold fixed at the innocent 80th percentile (Figure 3's
worked threshold); audit threshold set per k at the 99th percentile of the
innocent min distribution (Figure 4-right's vertical lines, 1% budget).

Auditing and the execute/defer decision are separate — with resampling the
recalibrated audit threshold can sit BELOW the defer threshold — so the
readouts use the module's win/continue/lose trichotomy as the mutually
exclusive outcomes for one attacked step: win = min above the audit
threshold ((1−F_A(t_a))·(1−F_M(t_a))^(k−1)); lose = an attack-typed min
below min(t_d, t_a), i.e. an attack executes with no audit (integrate the
attack-typed min density); continue = the rest (a benign sample or T's
action runs). Fourth readout: innocent step deferred to T
((1−F_I(t_d))^k — the usefulness win). Spliced with the
continuation-probability discussion (block b-0067).
